# The app: OData V2 and UI5 freestyle

*Kept small: one entity type, one function import, one view. The rules live in ABAP; the app interprets nothing.*

## The layers

```
UI5 freestyle              BSP ZCFL_00500_UIV2       one view, one controller
      │  OData V2
ZCL_ZCFL_00500_V2_DPC_EXT  (generated by SEGW)       two redefinitions, decides nothing
      │
ZCL_CFL_00500_V2_DATA      read · write · authorization      knows nothing about OData
      │
      ├─ workflow class    container helpers (GLOBAL FRIENDS)
      ├─ rules class       which reasons, which step is editable, what is missing
      └─ conFLOW           /C09/CFL_S01 · S03 · S04
```

**The data class is the part that lasts.** The DPC_EXT above it is a thin shell and can be dropped if the technology changes later.

## The SEGW model

Project `ZCFL_00500_V2`, **one** entity type `Decision`, **all properties `Edm.String`**. That way there is no precision, no scale and no hidden type derivation to get wrong when typing it in.

| Property | Max length | Content |
| --- | --- | --- |
| `WfId` (key) | 32 | conFLOW instance as hex string |
| `Title` | 120 | work item title (`SWWWIHEAD-WI_TEXT`) |
| `WorkitemText` | **empty** | the context block from `SAP_WAPI_WORKITEM_DESCRIPTION` |
| `ReasonList` | **empty** | allowed reasons as `KEY=Text`, one line per reason |
| `Reason` | 20 | input |
| `Note` | 132 | input, length of a container value |
| `Editable` | 1 | `X` / empty — the backend controls the fields with it |
| `MessageText` | 80 | why input is not possible, or what is missing for completion |

Entity set `DecisionSet`. In addition, under *Data Model*, a **function import** `SetDecision`:

| | |
| --- | --- |
| Return type kind / type | Entity Type / `Decision` |
| Return cardinality | `1` — saving returns the new state including `MessageText` right away |
| Return entity set | empty (cannot be set with cardinality 1) |
| HTTP method | **`POST`** |
| Parameters | `WfId` (32), `Reason` (20), `Note` (132), all `Edm.String` |

{% hint style="danger" %}
**`WorkitemText` and `ReasonList` without max length.** With a length, SEGW generates `CHAR(n)`, and `MOVE-CORRESPONDING` truncates without a message.
{% endhint %}

## The two ABAP classes

**`ZCL_ZCFL_00500_V2_DPC_EXT`** redefines exactly two methods:

| Method | Does |
| --- | --- |
| `DECISIONSET_GET_ENTITY` | unpack key → `READ` → `MOVE-CORRESPONDING`; nothing found → 404 |
| `/IWBEP/IF_MGW_APPL_SRV_RUNTIME~EXECUTE_ACTION` | unpack parameters → `SAVE` → return; rejected → exception **with text** |

No create, update, delete or entity set. What doesn't exist doesn't need securing.

**`ZCL_CFL_00500_V2_DATA`** has two public methods, `READ` and `SAVE`. Both run the same checks first:

| Check | How |
| --- | --- |
| valid key? | 32 hex characters |
| instance belongs to **this** workflow? | `/C09/CFL_S01-WF_DEFINITION` |
| which work item? | `/C09/CFL_S03` ⋈ `SWWWIHEAD` (type `W`), the open one first, otherwise the most recent |
| **is this user allowed?** | `SWWUSERWI` (open work item in the worklist) **or** `SWWWIHEAD-WI_AAGENT` (executed it) |

{% hint style="danger" %}
**The instance check is mandatory.** The PFCG role grants access to the *service*, not to specific instances — and the key is in the URL. Both reads go through the primary key and need no function module. "Not found" and "not authorized" return the same text, so that an outsider cannot find out which GUIDs exist.
{% endhint %}

`SAVE` writes **only on change** — otherwise every typing pause would reset the changed-by user and timestamp. It also saves incomplete input and reports via `MessageText` what is still missing for completion.

## The UI5 app

Freestyle, built against **SAPUI5 1.71**, only `sap.m`, `sap.ui.core` and `sap.ui.layout`.

| File | Content |
| --- | --- |
| `manifest.json` | data source `/sap/opu/odata/sap/ZCFL_00500_V2_SRV/`, OData 2.0, one root view, no router |
| `Component.js` | key from the startup parameters, work item switch |
| `view/Detail.view.xml` | panel with work item text, *Reason* select, *Note* text area, status line |
| `controller/Detail.controller.js` | read, save automatically, status line |
| `i18n/i18n.properties` | texts |

### The key and the work item switch

My Inbox passes the key as startup parameter `CFLQueryObject00`. Under `embedIntoDetailsNestedRouter` the app is **reused** when the user clicks the next work item. My Inbox then calls two methods on the component:

```js
wfIdOf: function (oParams) {                 // parameters arrive as arrays
    var v = oParams && (oParams.CFLQueryObject00 || oParams.WfId);
    return Array.isArray(v) ? v[0] : v;
},

navigateBasedOnStartupParameter: function (oParams) {   // required
    this.setWfId(wfIdOf(oParams));           // -> EventBus -> controller reloads
},

refreshForStartupParameter: function (oParams) {        // optional
    this.setWfId(wfIdOf(oParams));
}
```

{% hint style="danger" %}
**Without `navigateBasedOnStartupParameter`, only the buttons change on the second work item** — the content stays. The buttons come from the task gateway, the content from the app. Both methods are undocumented and were read from the My Inbox source code, so re-check them after upgrades. Report the switch via the **EventBus**: `JSONModel#setProperty` does not fire `propertyChange`.
{% endhint %}

### Reading and saving

- **Read once** (`DecisionSet('<id>')`) and put the values into a **JSON model**. The fields are bound to the JSON model, not to the OData binding — otherwise they would sit in the V2 model as pending changes.
- **No save button.** The conFLOW buttons are outside the app; nobody could collect an unsaved state at decision time. So the app saves when a reason is selected, and for the note after an **800 ms** typing pause (`liveChange`) and when the field is left (`change`).
- Saving uses `callFunction("/SetDecision", { method: "POST", … })`.
- **Don't re-read after saving.** Otherwise the value just read overwrites the field the cursor is still in.
- **Status line** instead of a dialog: green *Saved hh:mm*, yellow *saved, but … is missing for completion*, red with the backend text. A flag prevents duplicate calls.
- Both fields are bound to `Editable`. Which step allows input is defined in the rules class, not in JavaScript.

## Build and upload

The source project lives in Git; the system only holds the build result.

```
npm install
npm run build            # ui5 build → dist/ with Component-preload.js
cd dist && zip -r ../app.zip .
```

Upload without a system connection on the development machine: `SE38` → **`/UI5/UI5_REPOSITORY_LOAD`**, mode *Upload*, application `ZCFL_00500_UIV2`, code page `UTF-8`, directory = the **unzipped `dist/`**. Then the caches, see [Customizing](customizing.md).

{% hint style="info" %}
**Don't change individual files in SE80.** The app runs from `Component-preload.js`. A changed individual file is never requested, and there is no message. Changes always go through the source project, build and upload.
{% endhint %}
